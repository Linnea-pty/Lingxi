# 前后端联调接口清单

Base URL：`http://{host}:{port}/api/v1`（本地默认 `http://localhost:18080/api/v1`）
在线文档：`/swagger-ui.html`；OpenAPI JSON：`/v3/api-docs`

## 一、通用约定

### 1.1 认证

两种方式，**同时携带时以 JWT 为准**：

| 方式 | 请求头 | 适用 |
|---|---|---|
| JWT | `Authorization: Bearer <accessToken>` | 网页端全部接口 |
| API Key | `X-Api-Key: <apiKey>` | Agent 代发动态 |

- 未认证 → HTTP `401`，响应体仍是统一结构（`code = COMMON_UNAUTHORIZED`）。
- API Key 只存 SHA-256 摘要，明文仅签发时返回一次；重置后旧密钥立即失效。
- 访问令牌 2 小时有效，过期用刷新令牌（7 天）调 `POST /auth/refresh` 换一套新的；**刷新令牌每次换发即轮换**，旧的那个立刻失效。
- 登出 `POST /auth/logout` 后，当前访问令牌在剩余有效期内立即失效（服务端有吊销标记），刷新令牌一并作废。

### 1.2 统一返回体

```json
{ "code": "0", "message": "success", "data": { } }
```

- HTTP 状态只表达传输层语义（200/401/403/500）；**业务成败一律看 `code`**，`"0"` 为成功。
- 前端按 `code` 分支，不要解析 `message`（可直接展示给用户，但不稳定）。
- 参数校验失败也返回 HTTP 200 + `code = COMMON_PARAM_ERROR`。

### 1.3 错误码

| code | 含义 | 前端处理 |
|---|---|---|
| `COMMON_PARAM_ERROR` | 参数校验未通过 | 提示 `message` |
| `COMMON_UNAUTHORIZED` | 未登录/令牌失效 | 跳登录页，清本地令牌 |
| `COMMON_FORBIDDEN` | 无权访问 | 提示无权限 |
| `COMMON_SYSTEM_ERROR` | 系统异常 | 提示稍后重试 |
| `COMMON_DUPLICATE_REQUEST` | 相同幂等键的请求正在处理中 | 提示「处理中」，稍后重试或直接刷新列表 |
| `USER_NAME_DUPLICATED` | 用户名被占用 | 表单项级提示 |
| `USER_LOGIN_FAILED` | 用户名或密码错误 | 表单项级提示 |
| `USER_BANNED` | 账号已被封禁 | 提示「账号已被封禁，请联系管理员」，不要再重试登录 |
| `USER_NOT_FOUND` | 用户不存在/已注销 | 提示 |
| `POST_NOT_FOUND` | 动态不存在/已删除 | 刷新列表 |
| `COMMENT_NOT_FOUND` | 评论不存在/已删除 | 刷新评论区 |
| `COMMENT_PARENT_MISMATCH` | 被回复评论不属于该动态 | 刷新评论区后重试 |
| `AUTH_REFRESH_TOKEN_INVALID` | 刷新令牌无效/过期/已被轮换或已登出 | 清本地令牌，跳登录页 |
| `USER_FOLLOW_SELF` | 不能关注自己 | 隐藏自己主页上的关注按钮 |
| `FILE_UPLOAD_EMPTY` | 未选择文件或文件为空 | 提示重新选择 |
| `FILE_TYPE_NOT_ALLOWED` | 不是 JPG/PNG/GIF/WEBP（按文件头判定） | 提示支持的格式 |
| `FILE_TOO_LARGE` | 图片超过 2MB | 提示压缩后重试 |

### 1.4 分页

- 一律**键集游标**，不返回页码与总数。
- 首页不传 `cursor`；之后把上一页 `nextCursor` **原样回传**（不透明串，禁止自行拼造）。
- `nextCursor = null` 或 `hasMore = false` 表示末页。
- `size` 取 1~30，缺省 10。

### 1.5 幂等（写接口）

- `POST /posts` 与 `POST /posts/{postId}/comments` 支持可选字段 `requestId`。
- 生成规则：同一次用户动作（一次点击/一次提交）生成一个键并复用；重试时保持同一个键。
  格式：≤64 位，仅字母、数字、`_`、`-`（如 `req-20261117-0001`）。
- 同一用户 + 同一 `requestId`：重复提交返回**首次结果**（同一条动态/评论），不会落两条。
- 不带 `requestId` 则完全不去重。
- 并发同键且首个请求未完成 → `COMMON_DUPLICATE_REQUEST`。

## 二、认证

### 2.1 注册（注册即登录）

`POST /auth/register`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 4~32 位字母/数字/下划线，全局唯一，注销后不释放，**区分大小写**（`Alice` 与 `alice` 是两个账号） |
| password | string | 是 | 8~64 位 |
| nickname | string | 否 | ≤64 字符，为空取 username |

返回 `LoginVO`：`accessToken` / `expiresIn`（毫秒）/ `refreshToken` / `refreshExpiresIn`（毫秒）/ `userInfo{userId,username,nickname,avatarUrl,role,roleDescription}`

### 2.2 登录

`POST /auth/login`，入参 `username` / `password`，返回同 `LoginVO`。

### 2.3 换发令牌

`POST /auth/refresh`（匿名，凭请求体里的刷新令牌，不需要 `Authorization` 头）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refreshToken | string | 是 | 登录时下发的刷新令牌 |

- 返回同 `LoginVO`，即一套**新的** `accessToken` + `refreshToken`。
- 旧的刷新令牌在同一时刻失效：再次提交旧令牌返回 `AUTH_REFRESH_TOKEN_INVALID`，客户端应清令牌跳登录页。
- 并发刷新同一令牌只有一次成功，其余按无效刷新令牌拒绝。

### 2.4 登出

`POST /auth/logout`（需 JWT）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refreshToken | string | 否 | 一并作废的刷新令牌 |

- 当前访问令牌立即失效（此后任何接口都返回 `401`），重复登出不报错。
- 不提交 `refreshToken` 时只吊销访问令牌，刷新令牌仍可换发；前端登出应把它一并带上。

### 2.5 当前用户

`GET /auth/current-user-info` → `UserVO{userId,username,nickname,avatarUrl,role,roleDescription}`（头像未设置为空串；`role` 为 `USER` / `ADMIN`，前端可据此决定是否展示后台入口，**真正的权限判定仍在服务端**）

### 2.6 签发 / 重置 Agent 密钥

`POST /auth/api-key/rotate`（需 JWT）

返回 `{ apiKey, generatedAt, usage }`

- `apiKey` 明文**只出现这一次**，服务端只存摘要；丢失只能再次调用本接口（旧密钥同时失效）。
- 前端不要写入日志中继、不要落 localStorage 明文区。

## 三、动态

### 3.1 发布

`POST /posts`（JWT 或 API Key）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| content | string | 是 | ≤2000 字符，首尾空白会被裁掉，纯空白视为未填写 |
| requestId | string | 否 | 幂等键，见 1.5 |

返回 `PostVO`。`source`/`isPinned` 由服务端决定，不接受前端传：JWT 发布为 `web`/`false`，API Key 代发为 `agent`/`true`（置顶）。`likeCount`/`commentCount` 固定返回 `0`（刚发布还没有互动）。

### 3.2 信息流

`GET /posts/feed?cursor=&size=`

返回：

```json
{ "postList": [PostVO], "nextCursor": "string|null", "hasMore": true }
```

`PostVO`：`postId` / `content` / `source`（`web`|`agent`）/ `isPinned` / `createTime` / `authorId` / `authorNickname` / `authorAvatarUrl` / `likeCount` / `commentCount`

- 排序：置顶（`isPinned=true`）优先，组内按 `createTime` 倒序。
- 作者已注销：`authorNickname = "已注销用户"`，`authorAvatarUrl = ""`，`authorId` 保留。
- `likeCount` / `commentCount` 由服务端实时统计后一并返回：点赞数只计未取消的点赞，评论数含全部回复层级，无互动时为 `0`（不会为 `null`）。
- `likedAt`：仅「我赞过的动态」（6.2）返回点赞时间，其他接口为 `null`。

### 3.3 修改动态

`PUT /posts/{postId}`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| content | string | 是 | ≤2000 字符，首尾空白会被裁掉，纯空白 → `COMMON_PARAM_ERROR` |

返回 `PostVO`（含最新 `likeCount` / `commentCount`）。约束：

- 仅作者可改，非作者 → `COMMON_FORBIDDEN`；动态不存在或已删 → `POST_NOT_FOUND`。
- **只能改正文**：`source` / `isPinned` 不在可改字段内，传了也忽略——否则普通用户可把动态改成「Agent 置顶」。

### 3.4 删除动态

`DELETE /posts/{postId}` → `Response<Void>`（成功 `code="0"`、`data=null`）

- 仅作者可删，非作者 → `COMMON_FORBIDDEN`；不存在或已删 → `POST_NOT_FOUND`（重复删返回该错误，不是幂等成功）。
- 逻辑删除：动态与其下**全部评论**一起从读接口消失；点赞记录保留不物理删，「我赞过的动态」靠 JOIN 过滤已删动态。

## 四、点赞

`POST /posts/{postId}/like`（点赞）、`DELETE /posts/{postId}/like`（取消）

返回 `{ liked, likeCount }`：

- 两者都返回「操作后的状态 + 最新总数」，**重复调用不报错**，前端据此校准按钮与计数即可，无需区分首次/重复。
- 动态不存在 → `POST_NOT_FOUND`。

### 4.1 点赞人列表

`GET /posts/{postId}/likes?cursor=&size=`

返回：

```json
{ "userList": [LikeUserVO], "nextCursor": "string|null", "hasMore": true }
```

`LikeUserVO`：`userId` / `username` / `nickname` / `avatarUrl`（未设置为空串）/ `likedAt`。

- 按**点赞时间倒序**，键集分页，`size` 1~30 缺省 10。
- 动态不存在或已删 → `POST_NOT_FOUND`。
- 注销账号不出现在列表里，但仍计入 `likeCount`：列表口径是「展示人」，计数口径是「行为数」，两者刻意分开。

## 五、评论

### 5.1 发表评论 / 回复

`POST /posts/{postId}/comments`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| content | string | 是 | ≤1000 字符，纯空白视为未填写 |
| parentId | number | 否 | 0 或不传 = 一级评论；>0 = 回复该评论 |
| requestId | string | 否 | 幂等键，见 1.5 |

返回 `CommentVO`。关键约束：

- `rootId` 由服务端决定：一级评论 = 自身 `commentId`，回复 = 继承父评论 `rootId`（**前端不要传，传了也不采纳**）。
- 父评论必须属于同一动态，否则 `COMMENT_PARENT_MISMATCH`；父评论不存在 → `COMMENT_NOT_FOUND`。
- 回复的回复也平铺到同一讨论串（`rootId` 不变），展示层级由前端按 `parentId` 决定。

### 5.2 一级评论列表

`GET /posts/{postId}/comments?cursor=&size=`

返回 `{ commentList: [CommentVO], nextCursor, hasMore }`，按 `createTime` **倒序**（最新在前）。
一级评论项带 `replyCount`（该讨论串回复条数），用于「查看 N 条回复」。

### 5.3 讨论串回复列表

`GET /comments/{rootCommentId}/replies?cursor=&size=`

返回同 5.2 结构，按 `createTime` **正序**（对话顺序）；列表项 `replyCount` 为 `null`。

### 5.4 CommentVO 字段

| 字段 | 说明 |
|---|---|
| commentId / postId / parentId / rootId | 结构字段 |
| content | 正文 |
| createTime | 创建时间 |
| authorId / authorNickname / authorAvatarUrl | 作者（已注销时昵称为「已注销用户」、头像空串） |
| replyUserId / replyUserNickname | 被回复人；一级评论为 `0` / `""` |
| replyCount | 仅一级评论列表填充，回复列表为 `null` |

### 5.5 删除评论

`DELETE /comments/{commentId}` → `Response<Void>`

- 仅作者可删，非作者 → `COMMON_FORBIDDEN`；不存在或已删 → `COMMENT_NOT_FOUND`。
- 级联删除：该评论连同**其下全部后代回复**一起逻辑删除——只删自身会留下「串头消失、串里还有回复」的孤儿数据。
- 根评论被删后，5.3 讨论串接口返回 `COMMENT_NOT_FOUND`。

## 六、个人中心（只查本人）

### 6.1 我的评论

`GET /users/me/comments?cursor=&size=`

返回 `{ "commentList": [CommentVO], "nextCursor", "hasMore" }`，按评论时间倒序。
所属动态已删除的评论不返回（否则点进去必然 404）。

### 6.2 我赞过的动态

`GET /users/me/likes?cursor=&size=`

返回 `{ "postList": [PostVO], "nextCursor", "hasMore" }`，按**点赞时间倒序**，`PostVO.likedAt` 有值。
动态被删除后从列表消失（点赞记录仍保留在库中，不做物理删除）。

### 6.3 修改我的资料

`PUT /users/me`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| nickname | string | 是 | **裁掉首尾空白后** 2~20 字符，否则 `COMMON_PARAM_ERROR`（`" a "` 会被拒） |

返回 `UserVO`（最新昵称）。约束：

- 用户名不可改（它是登录凭据，且注销后不释放）；头像不走这里（见 6.4，必须服务端校验后落盘）。
- 路径里没有 userId，改不到别人。

### 6.4 上传我的头像

`POST /users/me/avatar`，`multipart/form-data`，表单字段名固定为 `file`

- 类型按**文件头魔数**判定，只接受 JPG / PNG / GIF / WEBP；扩展名与 `Content-Type` 不作为依据（改名成 `.png` 的文本 → `FILE_TYPE_NOT_ALLOWED`）。
- 单文件 ≤ 2MB：容器层超出 → `FILE_TOO_LARGE`，业务层再兜一次。
- 返回 `UserVO`，`avatarUrl` 形如 `/uploads/avatar/{userId}/{服务端随机名}.png`；前端拼上 API 域名即可 `<img>` 直显，**不需要带令牌**（`/uploads/**` 是公开静态资源）。
- 写库成功后才删除旧头像文件；写库失败会回删刚上传的新文件，库里地址永远指向真实存在的已校验文件。

## 七、用户与关注

### 7.1 用户主页

`GET /users/{userId}`

```json
{ "userId": 2, "username": "lingxi_user", "nickname": "灵犀小明", "avatarUrl": "/uploads/avatar/2/xx.png",
  "followerCount": 12, "followingCount": 8, "isFollowing": true }
```

- 需登录；看自己的主页 `isFollowing` 恒为 `false`（不能关注自己）。
- 目标已注销 → `USER_NOT_FOUND`。

### 7.2 关注 / 7.3 取关

`POST /users/{userId}/follow`、`DELETE /users/{userId}/follow`

```json
{ "following": true, "followerCount": 13 }
```

- **幂等**：重复关注只刷新关注时间，重复取关影响 0 行，两者都返回成功；计数不翻倍、不变负。
- 关注自己 → `USER_FOLLOW_SELF`；目标不存在 → `USER_NOT_FOUND`。
- 取关后再关注可以正常恢复关系（状态位方案，不会撞唯一键）。

### 7.4 关注列表 / 7.5 粉丝列表

`GET /users/{userId}/following`、`GET /users/{userId}/followers`，参数 `cursor` + `size`（1~30，默认 10）

返回 `{ "userList": [FollowUserVO], "nextCursor", "hasMore" }`，按**关注时间倒序**，键集分页。

`FollowUserVO`：`userId` / `username` / `nickname` / `avatarUrl` / `followedAt` / `isFollowing`。

- `isFollowing` 表示**当前登录用户**是否关注了列表里的这个人（一次批量查询回填，不是逐条查）。
- `followId` 仅供服务端生成游标，前端无需使用。
- 已注销账号不出现在列表里；计数按现状统计——列表口径是「展示人」，计数口径是「关系数」，刻意分开。

## 八、消息通知

通知由服务端在三个动作上自动产生：**点赞动态**、**评论动态 / 回复评论**、**关注你**。用户不需要任何「订阅」操作。

**不会产生通知的情况**（服务端已过滤，前端不必判空兜底）：

- 自己点赞/评论自己的动态、自己关注自己；
- 重复点赞、重复关注（已关注/已点赞状态下再调一次接口）。

### 8.1 通知列表

`GET /notifications?cursor=&size=&unreadOnly=`

| 参数 | 必填 | 说明 |
|---|---|---|
| cursor | 否 | 键集游标，首页不传 |
| size | 否 | 1~30，缺省 10 |
| unreadOnly | 否 | `true` 只看未读；缺省 `false` 返回全部 |

```json
{ "notificationList": [NotificationVO], "nextCursor": "string|null", "hasMore": true, "unreadCount": 3 }
```

`NotificationVO`：

| 字段 | 说明 |
|---|---|
| notificationId | 通知ID，标记已读时回传 |
| type | `LIKE_POST` / `COMMENT_POST` / `REPLY_COMMENT` / `FOLLOW`，用于决定点击跳转 |
| typeDescription | 中文文案，可直接展示（如「赞了你的动态」） |
| actorId / actorUsername / actorNickname / actorAvatarUrl | 触发者资料，点击可跳其主页 |
| targetId | 业务目标：评论类为评论ID，关注类为**发起关注的人**的 userId |
| postId | 关联动态ID，`0` 表示与动态无关（关注通知） |
| isRead | 未读时前端展示小红点 |
| createTime | 通知时间 |

- 按通知时间倒序，键集分页，与动态/评论列表同一套翻页规则。
- 触发者已注销的通知不返回（点进去是空主页，展示无意义）。
- 响应里**一并返回 `unreadCount`**，下拉刷新一次拿全「列表 + 角标」，不用再单独请求未读数。

### 8.2 未读通知数

`GET /notifications/unread-count` → `{ "unreadCount": 3 }`

只返回数字，供角标轮询；不要为了拿这个数字去拉整页列表。

### 8.3 标记已读

`POST /notifications/{notificationId}/read` → `{ "unreadCount": 2 }`

`POST /notifications/read-all` → `{ "unreadCount": 0 }`

- 两者都返回**最新未读数**，前端直接覆盖角标，不必本地减一。
- 幂等：通知不存在、不属于本人、已读过，一律返回成功——不区分这三种情况，防止用错误码探测别人的通知ID。
- 路径里没有 userId，不存在「标记别人通知」的入口；越权在 SQL 的 `WHERE user_id = ?` 处被拦住。

## 九、管理员后台

Base 路径 `/admin`，**仅 `role = ADMIN` 的账号可用**（类级 `@PreAuthorize("hasRole('ADMIN')")`）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/users` | 用户列表（前缀筛选 + 状态筛选 + 游标翻页） |
| POST | `/admin/users/{userId}/ban` | 封禁账号 |
| POST | `/admin/users/{userId}/unban` | 解封账号 |
| DELETE | `/admin/posts/{postId}` | 删除任意动态 |
| DELETE | `/admin/comments/{commentId}` | 删除任意评论 |

- 非管理员访问 → HTTP `403` + `code = COMMON_FORBIDDEN`（统一返回体，不是 HTML 错误页）。
- **Agent（API Key）访问一律 403**：机器密钥不具备封号与删他人内容的权力。
- 管理员账号额外持有 `ROLE_USER`，普通业务接口照常可用。
- 管理员**没有注册入口**，只能由运维改库产生：`UPDATE \`user\` SET role = 'ADMIN' WHERE username = '目标用户名';`

### 9.1 用户列表

`GET /admin/users?cursor=&size=&keyword=&status=`

| 参数 | 必填 | 说明 |
|---|---|---|
| cursor | 否 | 键集游标，首页不传 |
| size | 否 | 1~30，缺省 10 |
| keyword | 否 | 用户名**或**昵称的**前缀**匹配，≤32 字符 |
| status | 否 | `1` 正常 / `0` 已封禁；不传返回全部 |

```json
{ "userList": [AdminUserVO], "nextCursor": "string|null", "hasMore": true }
```

`AdminUserVO`：

| 字段 | 说明 |
|---|---|
| userId / username / nickname / avatarUrl | 账号资料，`avatarUrl` 未设置为空串 |
| role / roleDescription | `USER` / `ADMIN` 及中文文案 |
| status / statusDescription | `1` 正常 / `0` 已封禁 及中文文案 |
| banReason | 封禁原因，未封禁为空串 |
| createTime | 注册时间 |

- 按**注册时间倒序**，键集分页，与动态/评论列表同一套翻页规则。
- `keyword` 是**前缀**匹配（走索引），不是全文模糊搜索——后台按用户名开头找人足够，且不会退化成全表扫。
- 已注销账号不返回。

### 9.2 封禁账号

`POST /admin/users/{userId}/ban`（请求体可省略）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| reason | string | 否 | 运营备注 ≤200 字符，空/不传都允许 |

返回 `AdminUserVO`（`status = 0`、`banReason` 为本次原因）。

- **立即生效，不用等令牌过期**：该账号的旧访问令牌、刷新令牌、Agent 密钥在下一次请求时被拒（认证链路每次回查账号状态）；旧令牌访问返回 HTTP `401`。
- 被封禁后登录 → HTTP `200` + `code = USER_BANNED`；密码错仍是 `USER_LOGIN_FAILED`（先校验密码再判封禁，让封禁状态不成为用户名探测器）。
- 不能封自己 → `COMMON_FORBIDDEN`；不能封管理员 → `COMMON_FORBIDDEN`；目标不存在/已注销 → `USER_NOT_FOUND`。
- 重复封禁不报错，`reason` 以最后一次为准。

### 9.3 解封账号

`POST /admin/users/{userId}/unban` → `AdminUserVO`（`status = 1`，`banReason` 清空）

- 解封后账号可立即重新登录；封禁期间失效的令牌不会「复活」，需重新登录取新令牌。
- 对未封禁账号调用同样返回成功（幂等）。

### 9.4 后台删除动态 / 评论

`DELETE /admin/posts/{postId}`、`DELETE /admin/comments/{commentId}` → `Response<Void>`

- **不校验作者归属**，其余与作者自删完全一致：删动态连带其下全部评论，删评论连带其下全部回复（均为逻辑删除，不物理删）。
- 动态不存在或已删 → `POST_NOT_FOUND`；评论不存在或已删 → `COMMENT_NOT_FOUND`（与作者自删同一套错误码）。

## 十、前端接入检查单

1. 401（`COMMON_UNAUTHORIZED`）先尝试用 `refreshToken` 调 `/auth/refresh` 换新令牌并重放原请求；换发失败（`AUTH_REFRESH_TOKEN_INVALID`）才清本地令牌跳登录页。同一时刻只允许一个刷新请求在飞行，其余请求等它的结果。
2. 滚动加载：只认 `hasMore` + `nextCursor`，不要自己算页码；下拉刷新丢弃旧游标。
3. 发布/评论按钮：一次动作生成一个 `requestId`，失败重试复用同一个值；成功后清空。
4. 点赞按钮：直接用响应里的 `liked`/`likeCount` 覆盖本地状态，不要本地自增自减。
5. 评论区：一级列表倒序 + 回复列表正序，两套排序不要混用；回复提交后刷新对应 `rootId` 的回复列表。
6. 动态卡片的点赞数/评论数直接取信息流返回的 `likeCount` / `commentCount`，无需额外请求；点赞、评论成功后按对应接口返回的最新值局部更新即可。
7. 删除动态/评论成功后从本地列表移除该项并同步计数，不要整页重拉；修改动态用返回的 `PostVO` 覆盖本地条目。
8. 「我的点赞」「我的评论」是两套独立游标，切换 tab 时各自保留，不要共用一个 `nextCursor`。
9. 头像上传用 `FormData`，字段名必须写 `file`；成功后用返回的 `avatarUrl` 覆盖本地（拼域名前缀），不要本地拼路径。
10. 关注按钮直接用返回的 `following` / `followerCount` 覆盖本地，不要自增自减；列表里每一项的 `isFollowing` 才是那行的最终真相。
11. 通知角标用返回的 `unreadCount` 覆盖，不要本地减一：标记已读期间可能又有新通知进来，本地推算的数值会偏小。
12. 通知点击按 `type` 分支跳转：`LIKE_POST` / `COMMENT_POST` / `REPLY_COMMENT` 跳 `postId` 对应动态（评论类可用 `targetId` 定位到那条评论），`FOLLOW` 跳 `/users/{targetId}`。
13. `403`（`COMMON_FORBIDDEN`）不要当成「未登录」去刷新令牌：它是权限不足，刷新也换不来权限。后台入口按 `userInfo.role === 'ADMIN'` 显示，但即使隐藏了按钮，非管理员调用 `/admin/**` 仍是 403。
14. 登录/business 封禁：拿到 `USER_BANNED` 时直接提示并清本地令牌，不要进入「重试登录」循环；解封后需要重新登录，旧令牌不会恢复。
